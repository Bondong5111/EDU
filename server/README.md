# MY LIFE 통합 서버

이 서버 하나만 켜두면 됩니다.

- 🌐 **웹사이트 제공**: 휴대폰·PC 어디서든 같은 주소로 접속, 홈 화면에 앱처럼 설치 가능
- 🔒 **비밀번호 로그인** (30일 유지, 5회 틀리면 15분 잠금)
- ☁️ **모든 기기 자동 동기화**: 기록 한 건이 한 줄인 데이터베이스에 쌓고, 바뀐 줄만 주고받음
- 💾 **자동 백업**: 1시간마다 데이터베이스 사본을 `server/data/backups/`에 최근 48개 보관
- 📈 **토스증권**: 보유 주식·평가손익·환율 자동 갱신 (조회 전용, 주문 기능 없음)
- 📅 **구글 캘린더**: 한 번 연결하면 계속 유지, 일정 자동 가져오기 + 새 일정 구글에 추가
- 🍽️ **팻시크릿**: 기존 계정을 한 번 연결하면 식단(칼로리·탄단지)과 체중을 날짜별 기록으로 자동 가져오기 (조회 전용)

의존성 설치가 필요 없습니다. **Node.js 22.13 이상**이 필요합니다 (내장 SQLite 사용).

## 빠른 시작 (집 컴퓨터에서만 쓰기)

인터넷에 공개하지 않고 이 컴퓨터에서만 여는 가장 안전한 방식입니다.

```bash
npm run setup    # 로그인 비밀번호, (선택) 토스증권 키를 물어보고 server/.env 를 만들어 줌
npm run check    # (토스 키를 넣었다면) 토스증권에 실제로 조회해 보고 결과를 알려줌
npm start        # 서버 켜기 → 브라우저에서 http://localhost:8787
```

- `npm run setup`에서 입력한 비밀번호와 키는 화면에 보이지 않고, 이 컴퓨터의 `server/.env`(권한 600)에만 저장됩니다. 다시 실행하면 바꿀 항목만 고칠 수 있습니다.
- 토스증권은 허용 IP를 등록해야 합니다. `npm run setup`이 이 컴퓨터의 공인 IP를 알려주면 토스증권 Open API 설정에 등록한 뒤 `npm run check`로 확인하세요.
- 기본 설정(`HOST=127.0.0.1`)에서는 같은 컴퓨터에서만 접속됩니다. 휴대폰에서도 쓰려면 아래 3번의 터널이나 개인용 사설망이 필요합니다.

아래는 항목별 자세한 설명입니다.

---

## 1. 서버 컴퓨터 고르기

토스증권은 **미리 등록한 고정 IP**에서 온 요청만 받으므로 아래 중 하나에서 실행하세요.

| 선택지 | 장점 | 비용 |
|---|---|---|
| 집 PC · NAS · 라즈베리파이 | 데이터가 집에만 있음 | 전기료 (항상 켜둬야 함) |
| VPS (Oracle Cloud 무료 티어, AWS Lightsail 등) | 항상 켜져 있음, IP 고정 | 무료 ~ 월 몇 천원 |

> 토스증권을 안 쓸 거라면 IP 제약은 신경 쓰지 않아도 됩니다.

## 2. 설정 파일 만들기

`npm run setup`을 쓰면 질문에 답하는 것만으로 만들어집니다. 직접 만들려면:

```bash
cp server/.env.example server/.env
```

`server/.env`를 열어 채웁니다.

| 항목 | 필수 | 설명 |
|---|---|---|
| `APP_PASSWORD` | ✅ | 로그인 비밀번호 (8자 이상, 길게) |
| `BASE_URL` | ✅ | 휴대폰에서 접속할 주소. 예: `https://life.mydomain.com` |
| `TOSS_CLIENT_ID` / `TOSS_CLIENT_SECRET` | | 토스증권 WTS → 설정 → Open API에서 발급 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | | 아래 4번 참고 |
| `FATSECRET_CONSUMER_KEY` / `FATSECRET_CONSUMER_SECRET` | | 아래 5번 참고 |

`server/.env`와 `server/data/`는 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다.

## 3. 실행

```bash
npm start
# → MY LIFE 서버: http://127.0.0.1:8787
```

`npm start`는 `node --disable-warning=ExperimentalWarning --env-file=server/.env server/server.mjs`를 실행합니다.
Node 22에서는 내장 SQLite가 아직 실험 기능으로 표시되어 있어, 시작할 때 나오는 경고 문구를 숨기는 옵션입니다.

항상 켜두려면 pm2를 쓰면 편합니다.

```bash
npm i -g pm2
pm2 start npm --name mylife -- start
pm2 save && pm2 startup
```

### 휴대폰에서 접속할 HTTPS 주소 만들기 (Cloudflare Tunnel)

공유기 포트포워딩 없이 HTTPS 주소를 만들 수 있습니다.

```bash
# 빠른 테스트용 임시 주소
cloudflared tunnel --url http://127.0.0.1:8787
```

계속 쓰려면 Cloudflare 계정에 도메인을 연결하고 이름 있는 터널(예: `life.mydomain.com → http://127.0.0.1:8787`)을 만드세요.
그 주소를 `BASE_URL`에 넣고, 터널 뒤에서는 `TRUST_PROXY=1`로 두면 로그인 시도 제한이 실제 접속 IP 기준으로 동작합니다.

> 터널을 써도 토스증권으로 나가는 요청은 이 컴퓨터의 공인 IP에서 나가므로, 그 IP(`curl https://ifconfig.me`)를 토스증권 허용 IP에 등록하면 됩니다.

## 4. 구글 캘린더 연결 준비

1. [Google Cloud 콘솔](https://console.cloud.google.com/) → 프로젝트 생성 → **Google Calendar API** 사용 설정
2. **OAuth 동의 화면**: 사용자 유형 *외부*, 본인 계정을 테스트 사용자로 추가
3. **사용자 인증 정보 → OAuth 클라이언트 ID → 웹 애플리케이션**
   - 승인된 리디렉션 URI: `{BASE_URL}/api/google/callback`
4. 클라이언트 ID·보안 비밀을 `.env`에 넣고 서버 재시작 → 웹사이트 **설정 → 연동 현황 → 구글 계정 연결**

> ⚠️ OAuth 동의 화면이 **테스트** 상태면 구글이 7일마다 연결을 끊습니다. 계속 쓰려면 동의 화면을 **프로덕션으로 게시**하세요. 본인만 쓰는 앱이라 검증 신청은 필요 없고, 로그인할 때 "확인되지 않은 앱" 경고만 한 번 나옵니다.

## 5. 팻시크릿 연결 준비

팻시크릿 앱에 적어 둔 식단과 체중을 가져옵니다. 앱에서 쓰던 **기존 계정**을 그대로 연결합니다.

1. [platform.fatsecret.com](https://platform.fatsecret.com/)에서 개발자로 가입합니다 (무료 Basic 등급으로 충분).
2. 발급된 **OAuth 1.0** 키 두 개를 `.env`에 넣습니다. `Consumer Key` → `FATSECRET_CONSUMER_KEY`, `Shared Secret` → `FATSECRET_CONSUMER_SECRET` (OAuth 2.0용 Client ID/Secret이 아닙니다).
3. 서버를 재시작하고 웹사이트 **나 → 연동 · 설정 → 팻시크릿 계정 연결**을 누릅니다. 팻시크릿 로그인 화면에서 허용하면 돌아옵니다.

연결하면 지난 1년 치를 한 번 가져오고, 이후에는 화면을 열 때 1시간이 지났으면 이번 달과 지난달을 다시 가져옵니다.

- 가져오는 값: 날짜별 섭취 칼로리, 탄수화물·단백질·지방(g), 체중(kg). 음식 이름 같은 세부 항목은 가져오지 않습니다.
- 식단 값은 팻시크릿이 원본입니다. 팻시크릿에서 지운 날은 여기서도 식단 값이 지워집니다(기분·일기 등 다른 기록은 그대로).
- 접근 토큰은 `server/data/secrets.json`에만 저장되고 브라우저로 전달되지 않습니다. 서버는 일지 **조회**만 호출합니다.

> ⚠️ 이 연동은 공식 문서대로 만들고 모의 서버로 검증했지만, 실제 팻시크릿 계정으로는 아직 확인하지 못했습니다. 처음 연결할 때 오류가 나면 아래 문제 해결 표와 서버 로그를 확인하세요.

## 6. 휴대폰 홈 화면에 설치

- **안드로이드(Chrome)**: 주소 접속 → 메뉴 → *홈 화면에 추가* / *앱 설치*
- **아이폰(Safari)**: 공유 버튼 → *홈 화면에 추가*

## 데이터 · 보안

- 데이터: `server/data/mylife.db` (SQLite, 권한 600), 백업: `server/data/backups/` (1시간마다, 최근 48개)
- 이전 버전의 `db.json`이 있으면 처음 시작할 때 새 데이터베이스로 자동 변환하고 `db.json.migrated`로 이름을 바꿔 둡니다.
- 복구: 서버를 끄고 백업 파일을 `mylife.db`로 복사한 뒤 다시 켭니다. 각 기기는 로그아웃 후 다시 로그인하세요.
- 비밀값(세션 서명 키, 구글 refresh token, 팻시크릿 접근 토큰): `server/data/secrets.json`
- 토스증권 키는 `.env`에만 있고 브라우저로 전달되지 않습니다. 서버는 계좌·보유 주식·환율 **조회**만 호출합니다.
- 상태를 바꾸는 요청에는 커스텀 헤더가 필요하고(CSRF 방지), 정적 파일은 허용 목록에 있는 것만 제공합니다.
- 기기를 잃어버렸다면 **설정 → 모든 기기 로그아웃**.

## 문제 해결

| 증상 | 해결 |
|---|---|
| 토스가 되는지 모르겠음 | `npm run check` 실행. 계좌 수와 보유 종목 수가 나오면 정상 |
| 토스 `ip-not-allowed` | 서버 공인 IP가 토스증권 허용 IP에 없음 (가정용 인터넷은 IP가 가끔 바뀜) |
| 토스 `invalid_client` | client_id / client_secret 오타 |
| 토스 `token-revoked` 반복 | 같은 키를 다른 프로그램에서도 쓰고 있음 (클라이언트당 토큰 1개) |
| 구글 연결 후 `?google=error` | 리디렉션 URI가 `{BASE_URL}/api/google/callback`과 정확히 같은지 확인 |
| 구글이 일주일 후 끊김 | OAuth 동의 화면을 프로덕션으로 게시 |
| 팻시크릿 `API 오류 (5 …)` 또는 `(8 …)` | 키 오타, 또는 OAuth 2.0 키를 넣음. OAuth 1.0의 Consumer Key / Shared Secret이어야 함 |
| 팻시크릿 `API 오류 (21 …)` | 팻시크릿 개발자 페이지에서 허용 IP를 요구하는 경우. 서버 공인 IP를 등록 |
| 팻시크릿 `연결 시작 실패` | 키가 틀렸거나 팻시크릿 인증 서버가 요청을 막음. 서버 로그의 응답 문구 확인 |
| 팻시크릿이 `연결 안 됨`으로 바뀜 | 팻시크릿에서 앱 권한을 회수함. 다시 연결하면 됨 (가져온 기록은 유지) |
| 상단 아이콘이 📴 | 서버에 연결 안 됨. 바꾼 내용은 기기에 남아 있다가 연결되면 자동 저장 |
